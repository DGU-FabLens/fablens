# FabLens Project Source of Truth

## 1. 프로젝트 정체성

### 프로젝트명

**FabLens: Virtual Metrology 및 SPC 기반 CMP 공정 품질 의사결정 플랫폼**

### 한 줄 정의

PHM 2016 CMP 공정 센서 시계열을 웨이퍼·Stage 단위로 가공해 Material Removal Rate를 예측하고, 기본 SPC와 규칙 기반 판정을 이용해 추가 계측이 필요한 대상을 추천하며 판단 근거를 Dashboard에 제공하는 프로젝트입니다.

### 프로젝트 목적

단순히 회귀 모델의 성능을 비교하는 데서 끝내지 않습니다.

> 공정 데이터가 들어온 뒤 품질값을 예측하고, 통계적 이상 여부를 판단하며, 어떤 대상을 추가로 계측해야 하는지 설명 가능한 기준으로 제시하는 닫힌 흐름을 구현합니다.

### 대상

- 인원: 정보통신공학 계열 학부 4학년 2~3명
- 기간: 4주 MVP
- 활용: SK하이닉스 DMI, PE, 양산기술, Data Science 직무 포트폴리오

---

## 2. 해결하려는 문제

CMP 공정에서 모든 웨이퍼를 실제 계측하는 상황을 직접 재현할 수는 없습니다. 본 프로젝트는 공개 데이터를 이용해 다음 질문을 제한적으로 검증합니다.

> 공정 센서 정보로 MRR을 예측하고, 예측 결과와 SPC 상태를 이용해 추가 계측 우선순위를 정할 수 있는가?

이 프로젝트에서 추천하는 것은 **실제 계측을 대체하는 자동 판정**이 아닙니다. 모델이 제시한 결과를 근거로 **추가 확인이 필요한 대상을 선별하는 의사결정 보조**입니다.

## 3. 데이터와 분석 단위

### 데이터셋

- PHM 2016 CMP Data Challenge 공개 데이터
- 공정 센서 시계열과 wafer-stage별 평균 제거율 사용

### 목표값

- `AVG_REMOVAL_RATE`
- 프로젝트에서는 이를 MRR 품질값으로 표현합니다.

### 기본 분석 단위

- 원본 row 단위가 아니라 **wafer-stage 단위**
- 한 wafer-stage의 모든 시계열 row는 같은 train/validation/test 구간에 포함해야 합니다.
- Stage A와 B를 하나로 합칠지 별도 모델로 나눌지는 1주차 EDA 결과로 확정합니다.

### 데이터셋 확인 전 금지

- 컬럼 의미를 추측해 확정하지 않습니다.
- 데이터에 존재하지 않는 Recipe, Lot, 실제 규격 한계, 불량 라벨을 만들어내지 않습니다.
- 공개 데이터의 실제 파일 구조가 보고서 설명과 다르면 실제 파일을 기준으로 문서를 수정합니다.

## 6. 모델링 범위

### 비교 모델

- 선형 Baseline: Linear Regression, Ridge 또는 PLS 중 1개
- Random Forest Regressor
- XGBoost 또는 LightGBM 중 1개

모델 수를 늘리는 것보다 전처리, Feature 정의, 시간순 검증을 정확히 수행하는 것을 우선합니다.

### Feature 초기 후보

- 센서별 mean, std, min, max
- 시작–종료 변화량
- 시간에 따른 slope
- 공정 지속 시간
- pad·dresser 누적 사용 관련 값
- 직전 wafer-stage 대비 변화량
- Stage 또는 장비 조건

실제 컬럼과 데이터 분포를 확인한 뒤 선택하며, 첫 목표는 **설명 가능한 30~60개 Feature**입니다.

### 필수 모델 평가

- MAE
- RMSE
- R²
- 시간순 test 구간 결과
- Stage 또는 주요 조건별 성능 차이

Random split 결과는 참고용으로만 사용할 수 있습니다. 대표 결과는 시간순 검증으로 제시합니다.

## 7. SPC와 이상 정의

### Phase I

- 학습 또는 기준 구간의 실제 MRR을 이용해 중심선과 관리한계를 설정합니다.
- 기준 구간이 안정적인지 먼저 확인합니다.
- 안정적이지 않은 구간을 임의로 정상으로 간주하지 않습니다.

### Phase II

- 이후 시간 구간의 VM 예측 MRR을 관리도에 표시합니다.
- holdout 실제 MRR은 오프라인 평가에만 사용합니다.
- 실제 운영을 가정한 판단에서는 미래의 실제 MRR을 입력으로 사용하지 않습니다.

### 프로젝트 내부의 ‘이상’

- Phase I에서 만든 통계적 관리한계를 실제 MRR이 벗어난 holdout 샘플을 평가용 이상으로 정의할 수 있습니다.
- 이는 실제 반도체 불량 라벨이나 제품 규격 이탈을 의미하지 않습니다.

## 8. Rule-based 계측 우선순위

초기 규칙은 단순하고 설명 가능하게 유지합니다.

| 상태 | 예시 조건 | 조치 |
|---|---|---|
| 정상 | 데이터 품질 정상, 예측 MRR이 관리한계에서 충분히 떨어짐 | 일반 모니터링 |
| 주의 | 예측 MRR이 관리한계에 근접 | 추이 관찰 |
| 계측 권장 | 예측 MRR이 관리한계를 이탈 | 실제 계측 우선 대상 |
| 데이터 확인 | 결측·고정값·비정상 길이 등 입력 품질 문제 | 센서·데이터 확인 |
| 높은 우선순위 | 관리한계 이탈과 데이터 이상이 중첩 | 우선 검토 |

실제 데이터 확인 후 임계값을 확정합니다. 임계값을 결과에 맞춰 임의로 조절한 경우 반드시 기록합니다.

## 10. 완료 기준

아래가 모두 충족돼야 MVP 완료로 봅니다.

- 원본에서 wafer-stage 학습 테이블을 재생성할 수 있습니다.
- 데이터 Join 결과와 누락 건수를 기록합니다.
- 세 모델의 시간순 성능을 비교합니다.
- 미래 구간에 대한 SPC 관리도를 생성합니다.
- 실제 MRR을 사용하지 않고 계측 우선순위를 산출합니다.
- holdout 실제 MRR로 추천 정책을 사후 평가합니다.
- SHAP를 원인 후보로만 제시합니다.
- Streamlit에서 전체 흐름을 재현합니다.
- 실행 명령, 환경, Seed와 결과 파일이 기록됩니다.
- 공개 데이터 프로젝트의 한계를 README에 명시합니다.

## 11. 핵심 한계

- 실제 Fab 환경이 아닙니다.
- 실제 제품 불량·수율 데이터가 아닙니다.
- 통계적 관리한계는 실제 제품 Specification Limit이 아닙니다.
- SHAP는 인과관계를 증명하지 않습니다.
- 계측 우선순위는 실제 검사를 대체하지 않습니다.
- 공개 데이터에서 얻은 결과를 다른 장비·공정으로 일반화할 수 없습니다.
